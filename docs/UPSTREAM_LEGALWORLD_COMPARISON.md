# sii-research/Legal-world 上游代码级对照

- 审计对象：`https://github.com/sii-research/Legal-world.git`
- 独立克隆：仓库外只读工作副本（不进入公开材料）
- 固定提交：`979ee9619f187d227059316f849c17ecc530c816`
- 审计日期：2026-08-30
- 当前刑法仓库基线：本仓库`main`

## 结论

上游仍适合作为“法律智能体运行时和工具抽象”的参考，但不适合作为当前星火智学产品主线重新合并。它公开了民事咨询、文书、一审、上诉和二审的Agent运行时、工具/技能接口、人评及数据构建代码；没有课堂知识追踪、认知诊断、个性化路径、教师审核闭环、产品前端、多模态或数字人实现。

当前刑法仓库已有146个与上游同路径的tracked文件。抽样哈希显示文书比较、二审证人解析和gitskill关键管线仍与上游逐字一致；FSM、编排器、技术目录、文书registry和人评服务则已经刑法化或比赛化修改。正确策略是按能力复核和小范围移植，禁止覆盖式同步。

上游被审计提交没有tracked `LICENSE`/`COPYING`/`NOTICE`文件。新增逐字复制前应先确认授权；本轮只对已经存在的同源代码做审计，不新复制未知授权文件。

## 值得继续吸收的五点

1. **显式生命周期和阶段权限。**上游把场景、工具和角色权限分开，当前刑法版应继续保持manifest驱动，不让大模型自由改变流程。
2. **文书工具registry。**新刑事文书继续通过统一type→tool→result→renderer映射扩展，避免场景中硬编码。
3. **文书比较。**可用于“原稿—教师退回—学生修订稿”的结构化差异提示，但比较结果本身不评分。
4. **离线反思式Skill。**适合分析失败运行并生成候选技能改进；候选必须经过开发/教师审核，不能热更新正式课堂行为。
5. **人评和数据构建的可复现性。**保留输入版本、输出目录、哈希和失败样本，不把生成结果直接提升为法学金标准。

## 明确不应迁移的内容

- 民事原告/被告、起诉状和普通民事二审状态；
- 把PostgreSQL/Docker作为当前演示启动前置；
- 未经课程审核的法律persona、咨询参考答案或向量检索结果；
- 将gitskill自动成长直接作用于评分Rubric、法条结论或学生路径；
- 任何“上游已有多模态/数字人/课堂KT”的表述。
